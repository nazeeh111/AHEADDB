# AHEADDB Live 0.3.0

Public source CI and a fresh non-editable public installation passed. This
document records the changes and executed source checks; the
[GitHub Release](https://github.com/nazeeh111/AHEADDB/releases/tag/v0.3.0) records
the final release commit and asset-download verification.

AHEADDB Live adds an owned PostgreSQL prediction layer around the preserved
statistical engine. A developer can declare and evaluate a temporal task,
register a safe model recipe, publish a predictive view, change source records
and read an answer that identifies its source coverage and generation.

## Changes

- Versioned owned source rows, transactional outbox, durable snapshots/jobs and
  complete conditional publication with worker leases/fences.
- Typed Python HTTP SDK, v1 OpenAPI contract and `ahead live` CLI commands.
- Latest-published, retained-generation and bounded-freshness reads. Stale or
  unknown results require explicit opt-in; publication time is not source time.
- Full rebuild, durable FIFO/debounce and interpretable freshness-budgeted
  planning. Compatible features share work; deadlines and fairness remain explicit.
- Bounded backlog/retries, cancellation, retention, purge-ledger backup/restore
  and conservative clock-discontinuity handling.
- SignalDesk Live and a separate generic developer example using only the public
  SDK. Actual installed worker-loss recovery is recorded in the short demo.

The original library, statistical models, compatibility API and historical quality
reports remain available. This release does not claim a new predictive model.

## Executed local checks

The corrected suite passed 144 tests with six optional FastDFS tests skipped.
Ruff passed and mypy checked 22 source files. A fresh non-editable wheel install
ran the public developer example with Python isolated mode and no database setting
in its client process: source revision 1 advanced to 2 and both feature values
updated while model and cutoff stayed fixed.

The installed shop app hid current results after another edit. A worker was
killed at `compute_after`, before publication. A replacement published both views
at revision 2; the app showed 57.7% return probability and expected revenue 315.0
for the synthetic selected customer. These are integration values, not forecast
accuracy scores. Desktop and 390-pixel mobile previews were inspected.

Fault checks include independent public generation agreement, seven abrupt worker
boundaries, abrupt source transaction loss, poison work/backpressure, failed
migrations, a real full volume, and unclean PostgreSQL WAL recovery after an
acknowledged edit. See the [fault matrix](../live-verification.md).

All 90 frozen workload cases passed: 25,576 view-generations in 12,792 publication
batches and 1,636,864 independent prediction comparisons. All views reached the
acknowledged final boundary, and all 15 silence checks stayed fresh without new
refresh work. Budget planning reduced median deadline misses versus FIFO in all
six workloads and used less measured CPU in four, but sparse/overload CPU did not
improve, debouncing remained competitive, and tight deadlines were often missed.
Large variation between equivalent controls prevents a general speed claim.
See the [complete measurements and limits](../live-results.md).

## Install and limits

Use the [pinned checkout quickstart](../live-quickstart.md), Python 3.12 and a
separate local PostgreSQL development source. The `live` extra installs the HTTP
SDK and PostgreSQL client; no API key, model download or billed service is needed.
The wheel includes `py.typed`; the source archive includes the examples, lockfile,
HTTP contract and editable architecture diagram.

Live is loopback-only development software without authentication. External CDC,
production schema changes, rolling retraining, high availability and continuous
WAL/PITR disaster recovery are outside scope. Separate latest-view reads are not
mutually atomic. Purging invalidates models/generations; offline restore requires
the current external source-bound ledger. Preserve private backup contents.
Read [security guidance](../../SECURITY.md) and the
[consistency contract](../live-design.md) before using a real source.
